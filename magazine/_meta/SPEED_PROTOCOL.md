## 5대 속도 조치 (전부 100/100 + 금지어 0 유지가 조건)

1. **장 목표 크기 = 45~55KB** (현재 75~107KB의 절반).
   - 9단계 + [10단계] + 심층 G·H·I·J + 6페르소나 전원은 **그대로 유지**. 줄이는 건 각 발언/문단의 길이지 구조가 아니다.
   - score_chapter 구조 점수(40)·메타(20)·시뮬(20)는 분량이 아니라 요소 존재로 매겨지므로, 50KB로도 100점 가능. MIN_BYTES 30KB만 넘기면 됨.
   - 효과: 출력 토큰 ~절반 → 같은 세션 예산으로 ~1.8배 장 생산, 레이트리밋 빈도 ~절반.

2. **클린 골든 고정** (사후 금지어 치환 토큰 0으로):
   - 역사서 내러티브 골든 = `magazine/2KI/12/index.html` (금지어 0 검증본)
   - 선지서 골든 = `magazine/ISA/1/index.html` (72KB, 금지어 0)
   - 매 배치 동일 골든 재사용 — 입력 토큰 안정 + 금지어가 골든에서 전파되지 않음.

3. **분업 고정 (메인 세션 ↔ 백그라운드 엔진 충돌 회피)**:
   - 메인 대화 세션 = **역사서** 라인: 2KI 13~25 → 1CH 29 → 2CH 36 → EZR 10 → NEH 13 → EST 10
   - 백그라운드 엔진 = **선지서** 라인: ISA 17~66 → JER 52 → …
   - 서로 다른 책이므로 파일 충돌 없음. push 전 항상 `git pull --rebase origin main`.

4. **배치 = 6장 병렬 고정** (Agent 단일 메시지 6콜). 병렬 cap 16 내에서 안정적. 세션 한도 회복(매일 22:00 KST 등 리셋) 즉시 6장씩 재개. 부분 생성분이 100점이면 **반드시 즉시 커밋**(세션 한도 에러는 보고 반환 시점에만 터지고 파일·검증은 끝나 있는 경우가 많음 — 7-12 전례).

5. **금지어 사전봉쇄** (프롬프트에 종료조건으로 강제):
   - 각 서브에이전트 프롬프트 끝에: `작성 후 grep -nE '자리|박혀|박힌|박았|못박|박은|박아' <파일> 실행 → 검출 시 전부 치환 → 재실행 0건 확인 후에만 종료. 건너뛰지 마라.`
