# 네다바 SBM 관찰 앱 — 제작 기획서 (v1)

> "이해하지 못할 때 건넨 메시지" — 성령일 선교사가 지하교회의 탈북민에게 성경을 열어 주었던 그 사명을, 완성된 1189장 SBM 관찰이 앱으로 이어간다.

문서 버전: 1.0 · 상태: 킥오프 확정 · 작성: 오케스트레이터 종합

---

## 0. 확정된 범위 (킥오프)

- **배포**: 오프라인 PWA 기반 + 무료 OSS(Capacitor)로 iOS/Android 앱스토어 래핑. 개발·호스팅 전액 무료 스택. 실비는 스토어 등록비뿐(개발 비용 0).
- **기능**: 핵심 MVP를 극한 완성도로. 실시간 AI 도우미는 2차.
- **품질 목표**: 전문 에이전시 수주(₩30M) 수준 — 철저한 기획 → 제작 → 사용 시뮬레이션 → 피드백 → 리빌딩 반복 → 극한 완성.

## 1. 비전과 사명

### 1.1 한 줄 정의
성경을 혼자서는 이해하기 어려운 사람에게, "관찰"이라는 진입로를 통해 본문 스스로 말하게 하는 오프라인 우선 묵상 동반자.

### 1.2 사명 기준 (모든 설계 결정의 상위 규범)
1. **닿음(Reach)** — 저사양 폰·끊기는 망·제한된 환경에서도 작동
2. **쉬움(Ease)** — 무계정·무설치·링크 하나로 즉시
3. **이해(Understanding)** — 가르침이 아니라 관찰로, 처음 읽는 이의 진입로
4. **안전(Safety)** — 무추적·로컬 저장, 취약한 사용자 보호
5. **회복력(Resilience)** — 정적 사이트라 서버·USB·미러로 복제 가능

### 1.3 하지 않을 것 (비-목표)
- YouVersion·갓피플과 리더 기능으로 경쟁하지 않는다. 번역본 수집·읽기 계획 경쟁 ✗
- 계정·소셜·클라우드 동기화를 강제하지 않는다 ✗
- 관찰을 "해석/설교"로 덮어쓰지 않는다 — 관찰은 관찰로 유지 ✗

## 2. 사용자 페르소나

| # | 페르소나 | 상황 | 핵심 니즈 | 성공 기준 |
|---|---------|------|----------|----------|
| P1 | **첫 독자(선교 대상)** | 성경을 처음 접함, 배경지식 없음 | 한 장을 두려움 없이 이해 | 오늘 한 장을 끝까지 읽고 "무슨 뜻인지 알겠다" |
| P2 | **저사양·오프라인 사용자** | 구형 폰, 데이터 부족, 간헐적 망 | 한 번 받아 오프라인에서 전부 | 비행기 모드로 전권 열람·검색 |
| P3 | **설교 준비 목회자** | 시간 압박, 본문에서 개요 필요 | 관찰 → 설교 개요·근거절 빠르게 | 10분 내 한 장 관찰로 설교 뼈대 |
| P4 | **매일 묵상자** | 습관으로 매일 한 장 | 오늘의 관찰·메모·이어보기 | 7일 연속 방문, 메모 축적 |

## 3. 사용자 동선 (User Journey)

### 3.1 첫 방문 (P1·P2)
```
링크/QR 열기 → 스플래시(사명 한 줄) → "오늘의 관찰" 바로 →
읽기(9단계, 접힌 상태로 부담↓) → 하단 "홈 화면에 추가" 안내 →
(선택) 전권 목차 훑기 → 이탈해도 진도 자동 저장
```
핵심 원칙: **첫 화면에서 아무 선택 없이 곧바로 한 장을 읽게 한다.** 탐색·설정은 나중.

### 3.2 매일 재방문 (P4)
```
앱 아이콘 → 오늘의 관찰(어제 이어서) → 읽기 → 열린 질문 하나 붙들기 →
메모 남기기 → 북마크 → 이탈
```

### 3.3 설교 준비 (P3)
```
검색("새 언약") → 결과에서 장 선택 → 관찰 읽기 →
"꺼내쓰기" → 템플릿 선택(설교 개요/근거절/교차참조) →
결과 복사 → 외부(문서)로
```

### 3.4 오프라인 (P2)
```
최초 1회 온라인 → "전체 저장" 1탭 → 이후 완전 오프라인 →
검색·읽기·북마크·메모 모두 로컬에서 작동
```

## 4. 정보 구조 (IA)

```
앱 셸 (/app/)
├─ 오늘 (Today)          — 오늘의 관찰, 진도, 이어보기
├─ 성경 (Library)        — 66권 → 장 목차 (구약/신약, 장르 그룹)
│   └─ 장 (Chapter)      — 9단계 관찰 + 종합 A–J, 북마크/메모/꺼내쓰기
├─ 검색 (Search)         — 전권 전문 검색, 핵심어·책·장르 필터
├─ 내 서재 (My)          — 북마크·하이라이트·메모·진도 (로컬)
└─ 설정 (Settings)       — 글자 크기, 다크모드, 전체 저장, 언어(향후)
```

읽기 화면 하단 고정 액션바: **[◀ 이전] [북마크] [메모] [꺼내쓰기] [다음 ▶]**

## 5. 기능 명세 (MVP, EARS 요약)

### 5.1 오늘의 관찰
- WHEN 사용자가 앱을 열면, THE SYSTEM SHALL 마지막으로 읽은 다음 장을 "오늘의 관찰"로 제시한다.
- WHERE 진도 기록이 없으면, THE SYSTEM SHALL 창세기 1장을 시작점으로 제시한다.

### 5.2 전권 검색
- WHEN 사용자가 검색어를 입력하면, THE SYSTEM SHALL 1189장의 관찰 텍스트에서 일치 장을 관련도순으로 반환한다(오프라인, 로컬 인덱스).
- THE SYSTEM SHALL 책·장르 필터와 핵심어 하이라이트를 제공한다.

### 5.3 오프라인 전체
- WHEN 사용자가 "전체 저장"을 실행하면, THE SYSTEM SHALL 전권 데이터·검색 인덱스를 로컬 캐시에 저장하고 이후 무네트워크로 전 기능을 제공한다.

### 5.4 북마크·하이라이트·메모
- THE SYSTEM SHALL 장·구절 단위 북마크와 사용자 메모를 로컬(IndexedDB)에 저장하며, 서버로 전송하지 않는다.

### 5.5 꺼내쓰기(추출 템플릿) — 오프라인은 규칙 기반, 온라인은 AI(2차)
- WHEN 사용자가 "꺼내쓰기"를 선택하면, THE SYSTEM SHALL 현재 장 관찰에서 [설교 개요 / 묵상 질문 / 근거절 / 교차참조] 형식으로 재구성한 텍스트를 복사 가능하게 제시한다.
- v1(오프라인): 관찰의 종합·열린 질문·근거절 필드를 템플릿으로 조립.
- v2(온라인): 클로드 API로 동적 생성.

### 5.6 접근성·저사양
- THE SYSTEM SHALL WCAG 2.1 AA를 충족한다(대비·키보드·스크린리더·글자 확대).
- THE SYSTEM SHALL 최초 로드 100KB 미만 셸 + 지연 로딩으로 구형 기기에서 작동한다.

## 6. 기술 스택 (전액 무료·초경량·미러 가능)

| 층 | 선택 | 이유 |
|----|------|------|
| 셸/UI | **바닐라 JS + 경량 CSS** (기존 사이트 자산 재사용, 프레임워크 없음) | 초경량·무의존·미러 배포·구형 기기. 빌드 파이프라인 없이 정적 서빙 |
| 데이터 | **정적 JSON** (장별 + 검색 인덱스) | 서버 불필요, CDN·오프라인·USB 어디서나 |
| 검색 | **클라이언트 로컬 인덱스** (경량 전문 검색, 무외부) | 오프라인·무추적 |
| 저장 | **IndexedDB / localStorage** | 로컬 전용, 무계정 |
| 오프라인 | **Service Worker (기존 sw.js 확장)** | 이미 존재, 앱 셸+데이터 캐시 |
| 설치 | **Web App Manifest (기존 확장)** | 홈 화면 추가 |
| 스토어 | **Capacitor (OSS)** | PWA를 iOS/Android로 무료 래핑, 재작성 0 |
| 호스팅 | **GitHub Pages / Vercel (무료)** | 기존 배포 그대로 |
| 분석 | **없음(무추적)** 또는 서버리스 무쿠키 카운트만 | 사명(안전) |

> AI 도우미(2차)만 서버리스 엣지 함수 + 클로드 API 키가 필요. v1은 서버 0.

## 7. 데이터 스키마 (Phase 0 산출물)

```json
  "book": "JER",
  "book_ko": "예레미야",
  "book_en": "Jeremiah",
  "chapter": 31,
  "testament": "OT",
  "genre": "선지서",
  "essence": "2문장 요지 (책 인덱스 카드에서)",
  "synthesis": "종합 A–J 관찰 본문 (정제 텍스트)",
  "keywords": ["새 언약", "라헬", "에브라임", ...],
  "prev": "JER-030",
  "next": "JER-032",
  "url": "/magazine/JER/31/"
}
```

### 7.2 검색 인덱스 `app/data/search-index.json`
```json
[
  { "id": "JER-031", "book_ko": "예레미야", "ch": 31, "genre": "선지서",
    "title": "예레미야 31장", "snippet": "…", "keywords": [...] }

```
경량(장당 수백 바이트) — 전체 1189장이 수 MB 이내로 오프라인 탑재 가능.

## 8. 시뮬레이션·피드백 방법론 (핵심 요청)

### 8.1 루프
```
빌드 → 페르소나 시뮬레이션 → 피드백 리포트 → 우선순위 → 리빌딩 → (반복)
```
점수(사용성·접근성·완성도)가 **연속 2회 수렴**할 때까지 반복.

### 8.2 페르소나 시뮬레이션
각 페르소나(P1–P4)의 대표 시나리오를 전문 에이전트가 실제 동선으로 "사용"하며 기록:
- **막힘**: 다음 행동을 못 찾은 지점
- **헷갈림**: 라벨·구조가 모호한 지점
- **불필요**: 목표까지 남는 잉여 클릭·화면
- **빠짐**: 있어야 할 안내·상태·피드백의 부재
- **좋음**: 유지·강화할 강점

### 8.3 피드백 리포트 포맷
| 항목 | 페르소나 | 심각도 | 판정 | 근거 | 조치 |
|------|---------|--------|------|------|------|
| 예: 검색 결과에 책 필터 없음 | P3 | 높음 | 강화 | 설교자 동선 3클릭 낭비 | 필터칩 추가 |

판정: **유지 / 수정 / 제거 / 강화**.

### 8.4 완성 게이트 (통과 필수)
- 사용성: 각 페르소나 핵심 과업 성공률 100%, 3클릭 이내 도달
- 접근성: WCAG 2.1 AA (pa11y 0 오류)
- 성능: Lighthouse PWA/성능/접근성/모범사례 ≥ 90
- 오프라인: 비행기 모드 전 기능 작동
- 경량: 셸 < 100KB, 전체 저장 < 5MB(gzip)
