Part 05
실행 로드맵
한 번에 다 하지 않습니다. 급한 것부터, 효과 큰 것부터.
PHASE 1
1~2주 · 기초 인프라
사이트 뼈대 정리
  • index.html 리디자인 (company/programs/story와 톤 통일)
  • 폴더 구조 재편 (루트 → 카테고리별 분류)
  • .gitignore + git config 세팅
  • 공통 CSS/JS 분리 (각 HTML 인라인 → 공유 파일)
PHASE 2
2~3주 · 포트폴리오 시스템
프로젝트 사례 체계화
  • /portfolio/ 케이스 스터디 HTML 템플릿 제작
  • 시온빌·이어도·한림항공우주고 사례를 개별 페이지로
  • 결과보고서 HTML 템플릿 (교육 끝 → 채우고 → 바로 공개)
  • 포트폴리오 인덱스 페이지 (카드형 목록)
PHASE 3
3~4주 · 업무 템플릿
반복 업무 템플릿화
  • 제안서 HTML 템플릿 3종 (기관용·기업용·공공기관용)
  • 교육계획서 HTML 템플릿
  • 워크시트 웹 버전 (강점진단 8종 등)
  • 자가진단 웹 도구 (행동분석 진단 등 → 결과 자동 표시)
PHASE 4
4~6주 · 콘텐츠 채널
블로그 + 유튜브 시동
  • 네이버 블로그 개설 + 키워드 전략 수립
  • 첫 블로그 글 5개 작성 (검색 유입용 핵심 키워드)
  • 유튜브 채널 세팅 + 첫 영상 3개 (3분 책리뷰)
  • 사이트에 블로그·유튜브 연결 허브 페이지
PHASE 5
6주~ · 자동화
반복을 줄이는 자동화
  • GitHub Actions 자동 배포
  • 결과보고서 → 블로그 글 자동 변환 워크플로우
  • 유튜브 스크립트 → 블로그 글 변환
  • 교육 문의 폼 → 이메일 + 이슈 자동 생성
Part 06
운영 원칙 4가지
홈페이지 = 쇼룸, 블로그 = 유입, 유튜브 = 신뢰
세 채널이 각자 다른 역할. 홈페이지에서 블로그 글을 쓸 필요 없고, 유튜브에서 회사소개를 할 필요 없습니다. 역할을 나누고, 같은 콘텐츠를 형태만 바꿔서 3곳에 올립니다.
한 번 만들면 계속 쓰는 구조
제안서 템플릿을 한 번 만들면, 다음 의뢰 때는 기관명과 날짜만 바꿉니다. 결과보고서 템플릿을 한 번 만들면, 교육 끝나고 30분이면 보고서가 완성됩니다. 1인이 감당하려면 구조를 만들어야 합니다.
오프라인 산출물 = 온라인 자산
제안서를 쓰면 → 포트폴리오에 올리고, 결과보고서를 쓰면 → 블로그에 사례로 올리고, 강의를 하면 → 유튜브에 핵심 3분 올립니다. 오프라인에서 한 일이 온라인 자산으로 쌓이는 순환.
Claude Code가 반복을 줄여준다
"이 결과보고서 데이터로 블로그 글 초안 써줘", "이 책 요약해서 3분 스크립트 만들어줘", "제안서 템플릿에 OO기관 정보 넣어줘" — AI가 반복 작업을 담당하고, 창환님은 현장과 사람에 집중합니다.
