Part 00

지금 당장 해야 할 세팅 3가지

현재 gitconfig도 없고, .gitignore도 없는 상태입니다. 5분 안에 끝납니다.

SETUP 01 · 5초
Git 이름·이메일 설정 (필수)
지금은 매 커밋마다 "Your name and email address were configured automatically" 경고가 뜹니다. 한 번만 설정하면 영원히 사라집니다.
터미널
git config --global user.name "Kim Changhwan"
git config --global user.email "nedabah.way@gmail.com"
💡
이 이름·이메일은 커밋 기록에 남는 작성자 표시입니다. GitHub 계정 이메일과 같으면 커밋이 프로필에 자동 연결됩니다.
SETUP 02 · 1분
.gitignore 만들기 (보안)
.env, 비밀번호, API키가 실수로 GitHub에 올라가면 — 삭제해도 이력에 영원히 남습니다. 미리 차단하는 게 .gitignore입니다.
nedabahway-site/.gitignore
# macOS 시스템 파일
.DS_Store
Thumbs.db

# 에디터 설정
.vscode/
.idea/
*.swp

# 비밀정보 (절대 올리면 안 됨)
.env
.env.local
*.key
*.pem
config.json

# 빌드 / 임시파일
node_modules/
dist/
*.tmp
*.bak
*.log
⚠️
중요: .gitignore는 '앞으로 올리지 마라'는 규칙입니다. 이미 올라간 파일은 적용 안 됩니다. 이미 올렸다면 git rm --cached 파일명으로 기록에서 빼야 합니다.
SETUP 03 · 1분
gh CLI 로그인 (이미 설치됨)
gh는 GitHub 전용 CLI입니다. 이미 설치되어 있지만, 로그인이 안 되어 있을 수 있습니다.
터미널
gh auth status     # 현재 로그인 상태 확인
gh auth login      # 로그인 (브라우저가 열림)
GitHub.com 선택
HTTPS 선택
Login with a web browser 선택 → 브라우저에서 코드 입력
완료. 이제 터미널에서 GitHub의 거의 모든 기능을 사용 가능
Part 01

매일 쓰는 Git
— 이것만 알면 된다

지금 nedabahway-site에서 실제로 쓰는 패턴 기준입니다. 복잡한 브랜치 전략은 1인 개발자에게 필요 없습니다.

GIT 01
일상 루틴: 수정 → 확인 → 올리기
매일 이 순서
# 1. 지금 뭐가 바뀌었는지 확인
git status

# 2. 바뀐 파일 중 올릴 것만 선택
git add company.html programs.html    # 파일 이름 지정

# 3. "왜" 바꿨는지 메시지 작성
git commit -m "프로필 타임라인 교육인턴 추가"

# 4. GitHub에 올리기 (= 사이트 반영)
git push
⚠️
git add .(점)은 모든 파일을 올립니다. .env나 비밀 파일이 섞일 수 있으니, 파일명을 지정하는 습관이 안전합니다.
GIT 02
뭔가 잘못됐을 때 — 되돌리기
커밋하기 전과 후로 나뉩니다. 커밋 후에는 조심해야 합니다.
상황명령어설명
수정 취소
(커밋 전)		git checkout -- 파일명마지막 커밋 상태로 파일 되돌림
add 취소git reset HEAD 파일명스테이지에서 빼기 (수정은 유지)
마지막 커밋
메시지 수정		git commit --amend -m "새 메시지"직전 커밋만 가능. push 전에만
이전 상태 보기git log --oneline -10최근 10개 커밋 목록
특정 커밋의
파일 복원		git checkout 커밋ID -- 파일명해당 시점의 파일만 가져옴
🚫
git reset --hard와 git push --force는 절대 쓰지 마세요. 되돌릴 수 없는 파괴적 명령입니다. Claude Code도 특별히 요청하지 않으면 이 명령을 실행하지 않습니다.
GIT 03
큰 작업할 때 — 브랜치 사용
새 페이지를 만들거나 디자인을 바꿀 때, main을 건드리지 않고 실험할 수 있습니다. 실패하면 버리면 됩니다.
브랜치 = 안전한 실험실
# 1. 새 브랜치 만들고 이동
git checkout -b feature/new-about-page

# 2. 마음껏 작업...
# 3. 만족하면 main에 합치기
git checkout main
git merge feature/new-about-page
git push

# 4. 쓴 브랜치 삭제 (정리)
git branch -d feature/new-about-page
✅
1인 개발자 규칙: 오타·작은 수정은 main에 바로 커밋. 새 페이지·큰 변경은 브랜치. 브랜치는 1~2일 안에 합치고 삭제. 이게 전부입니다.
Part 02

GitHub에서
90%가 모르는 기능들

push/pull만 쓰고 있다면 GitHub의 10%만 쓰고 있는 겁니다. 나머지 중 진짜 쓸모있는 것만 골랐습니다.

GITHUB 01
GitHub Actions — 자동 배포 (한 번 설정, 평생 편함)
지금은 git push하면 GitHub Pages가 알아서 배포합니다. 하지만 Actions를 설정하면 배포 전에 링크 체크, 이미지 최적화 같은 자동 작업을 추가할 수 있습니다.
프로젝트 폴더에 .github/workflows/ 폴더 생성
아래 YAML 파일을 deploy.yml로 저장
push하면 Actions 탭에서 자동 배포 로그 확인 가능
.github/workflows/deploy.yml
name: Deploy to GitHub Pages
on:
  push:
    branches: [ main ]
  workflow_dispatch:  # 수동 실행 버튼 추가

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - uses: actions/deploy-pages@v4
💡
설정 후 GitHub → Settings → Pages → Source를 "GitHub Actions"로 변경해야 작동합니다.
GITHUB 02
Issues — 나만의 할일 관리자
GitHub Issues를 버그 리포트가 아니라 할일 관리자로 씁니다. 코드 바로 옆에 있어서 맥락이 끊기지 않습니다.
터미널에서 바로
# 할일 만들기
gh issue create --title "story.html 사진 추가" --label content

# 내 할일 보기
gh issue list

# 완료 처리
gh issue close 3

# 브라우저에서 보기
gh browse --issues
📌
추천 라벨: content 콘텐츠 추가 · fix 수정 · design 디자인 변경 · idea 아이디어 · urgent 급한 것. 터미널에서 gh label create content --color 0E8A16로 만들 수 있습니다.
GITHUB 03
Releases — 버전 기록 남기기
큰 업데이트를 했을 때 "여기가 버전 1.0이다"라고 표시해두면, 나중에 그 시점으로 돌아갈 수 있습니다.
터미널
# 릴리즈 만들기
gh release create v1.0 --title "첫 공개 버전" \
  --notes "회사소개, 교육포트폴리오, 김창환이야기 3페이지 완성"

# 모든 릴리즈 보기
gh release list
Part 03

MCP
— Claude에게 손을 달아주는 법

MCP(Model Context Protocol)는 Claude가 파일 읽기, 브라우저 조작, GitHub 관리 같은 '행동'을 할 수 있게 해주는 연결 장치입니다. 지금 이미 쓰고 있는 것도 있습니다.

MCP 01
이미 쓰고 있는 MCP 도구들
도구상태할 수 있는 일
Claude in Chrome✅ 사용 중브라우저 조작, 스크린샷, 페이지 읽기, 폼 입력, 클릭
Claude Code✅ 사용 중파일 읽기/쓰기, 터미널 명령, git 조작
Canva 커넥터✅ 연결됨Canva 디자인 관리
Google Calendar✅ 연결됨일정 관리
Gmail✅ 연결됨메일 관리
MCP 02
추가하면 유용한 MCP 서버
서버할 수 있는 일설치 가치
GitHub MCPClaude가 직접 Issue 만들기, PR 관리, 코드 검색★★★ 강추
Filesystem MCPClaude Desktop에서 로컬 파일 읽기/쓰기★★☆ 유용
💡
Claude Code를 쓰고 있으면 Filesystem은 이미 내장되어 있습니다. Filesystem MCP 서버는 Claude Desktop(앱)에서 파일을 다룰 때 필요합니다.
MCP 03
GitHub MCP 서버 설치 방법
이걸 설치하면 Claude에게 "이슈 만들어줘", "PR 목록 보여줘" 같은 요청을 할 수 있습니다.
GitHub Personal Access Token 발급: github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate
권한 설정: Contents (Read/Write), Issues (Read/Write), Pull requests (Read/Write)
Claude Code에서 등록:
터미널 · Claude Code
claude mcp add-json github '{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": {
    "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_여기에토큰"
  }
}'

# 확인
claude mcp list
🔒
토큰 보안: 이 토큰은 GitHub 비밀번호와 같습니다. 절대 커밋하거나 공유하지 마세요. 유출되면 즉시 github.com에서 삭제하세요.
MCP 04
Claude in Chrome — 이런 것까지 됩니다
이미 설치된 Chrome MCP로 할 수 있는 실전 시나리오들입니다.
🖥 사이트 확인
"nedabah.org 열어서 모든 링크 눌러보고 깨진 거 있는지 알려줘"
📸 스크린샷
"내 사이트 스크린샷 찍어서 모바일에서 어떻게 보이는지 확인해줘"
📝 정보 수집
"이 교육 공고 페이지에서 마감일, 대상, 신청 방법 정리해줘"
📋 폼 자동화
"이 지원서 양식에 내 프로필 정보로 작성해줘" (확인 후 제출)
Part 04

실전 워크플로우

nedabahway-site 기준, 실제로 이렇게 일합니다.

WORKFLOW 01
사이트 콘텐츠 수정 — 전체 흐름
실전 시나리오: 교육 프로그램 페이지 수정
# 1. 아침에 할일 확인
gh issue list

# 2. Claude Code에게 요청
#    "programs.html의 Module 02에 ChatGPT 활용법 추가해줘"
#    → Claude가 파일 읽고 수정하고 diff 보여줌

# 3. 확인하고 올리기
git add programs.html
git commit -m "Module 02에 ChatGPT 활용법 추가"
git push

# 4. 1~2분 후 사이트 반영 확인
#    Claude: "nedabah.org/programs.html 열어서 확인해줘"

# 5. 이슈 닫기
gh issue close 7
WORKFLOW 02
새 페이지 추가 — 브랜치 활용
실전 시나리오: 새 교육자료 페이지
# 1. 안전한 실험실(브랜치) 만들기
git checkout -b feature/ai-workshop-material

# 2. Claude Code에게 페이지 제작 요청
#    "기존 programs.html 스타일 참고해서 AI 워크숍 교재 페이지 만들어줘"

# 3. 수정·테스트·만족할 때까지 반복
git add ai-workshop.html
git commit -m "AI 워크숍 교재 페이지 초안"

# 4. 만족하면 main에 합치기
git checkout main
git merge feature/ai-workshop-material
git push

# 5. 브랜치 정리
git branch -d feature/ai-workshop-material
