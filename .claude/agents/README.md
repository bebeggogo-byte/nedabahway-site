# 네다바웨이 조직도 — 자율 운영 루프

1인 교육기업 네다바웨이의 사이트·콘텐츠·수주 경로를 자율적으로 굴리기 위한 8부서 구조.

## 조직도

```
                       ┌─────────────┐
                       │  대표실       │  목표·피드백·개선 결정
                       │  chief       │  영업·외부노출 총괄
                       └──────┬──────┘
                              │ 지시·회고
                       ┌──────▼──────┐
                       │  전략실       │  스프린트 분해·배정·회고
                       │  strategist  │
                       └──────┬──────┘
                              │ 과업 배정
          ┌─────────┬─────────┼─────────┬─────────┐
          ▼         ▼         ▼         ▼         ▼
      ┌───────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
      │ 편집국  │ │ 연구소   │ │ 제작소   │ │ 디자인실 │ │ 기술실   │
      │ editor │ │research│ │producer│ │designer│ │engineer│
      └───┬───┘ └───┬────┘ └───┬────┘ └───┬────┘ └───┬────┘
          │         │         │         │         │
          └─────────┴─────┬───┴─────────┴─────────┘
                          ▼
                    ┌──────────┐
                    │  감수실    │  출고 전 전수 검수
                    │   qa     │  수정은 담당 부서로 반려
                    └──────────┘
```

## 자율 루프 프로토콜 (한 사이클)

```
1. [PLAN]   chief  → 이번 사이클 목표 1문장 선언
2. [BREAK]  strategist → 2~5일 스프린트로 분해, 부서 배정
3. [EXEC]   각 부서 → 병렬 실행. 한 과업 = 한 산출물
4. [CHECK]  qa → 전수 검수. FAIL 있으면 담당 부서로 반려
5. [MERGE]  chief → 통합 판단·커밋·배포
6. [RETRO]  strategist → 달성률·병목 분석·개선 제안 1~3개
7. [IMPROVE] chief → 개선점을 다음 사이클 목표에 반영하고 1번으로
```

## 부서 요약

| 부서 | 역할 | 주요 산출물 |
|------|------|-------------|
| **chief** | 목표·피드백·개선·영업 | 사이클 선언문, 통합 판단, CTA 일관성 |
| **strategist** | 분해·배정·회고 | 스프린트 계획, 회고 보고서 |
| **editor** | 매거진·사이트 카피 | `blog/posts/*.html`, 홈·리드 문구 |
| **researcher** | 근거·출처·팩트체크 | 자료실 근거자료, 포스트 인용 |
| **producer** | 실무 자산 템플릿화 | `resources/templates/`, `/worksheets/`, `/tools/`, `portfolio/case-*.html` |
| **designer** | 두 톤(다크/라이트) 일관성 | CSS 변수·여백·반응형 규칙 |
| **engineer** | SEO·a11y·성능·배포 | sitemap.xml, meta, canonical, 링크 무결성 |
| **qa** | 출고 전 검수 | FAIL/WARN/PASS 보고서 |

## 경계

- **부서 간 실무 교차 금지**: 편집국은 코드 수정 안 함, 기술실은 카피 안 씀, 대표실/전략실은 실무 안 함(결정·계획만).
- **빌드 시스템 금지**: 바닐라 HTML/CSS/JS. GitHub Pages 정적 호스팅.
- **유료 SaaS·외부 analytics 금지**: 현재 Formsubmit.co(문의) + Pretendard·Noto Serif CDN만.
- **1인 기업 시간 제약**: 한 사이클 전체 노동량은 주 5시간 이내로 설계.

## 사용법

- 이 저장소에서 `Agent(subagent_type="chief", ...)`처럼 부서명으로 호출.
- 새 사이클 시작: `chief`를 먼저 호출해 목표를 선언받고, 그 결과를 `strategist`에 넘겨 분해.
- 분해된 과업은 각 부서에 **병렬**로 디스패치. 단, 의존 관계(예: researcher→editor)는 직렬.
- 한 사이클 종료 전 반드시 `qa` 통과 → `chief` 머지 → `strategist` 회고.
