## 4. 글쓰기 전략 & 글 구조 템플릿

네이버 모바일 가독성 + AI검색(GEO) 인용 적합성을 동시에 노린다.

### 4.1 표준 글 구조
1. **후킹 도입(2~3문장)**: 실제 일화/장면으로 시작. "한 [역할]이 …" 또는 질문.
2. **핵심 단언 1문장**: AI가 그대로 인용할 수 있는 명제(= GEO 인용 단위). 좌표/프레임워크 연결.
3. **본문 3블록**: 소제목(H2/H3) + 각 블록 100~250자. 고유 IP(IDEN/5S/STARCP 등) 1개 이상 구체 적용.
4. **구체 근거**: 실제 강의·코칭·관찰 1건 또는 근거자료(124편) 1건. 날짜·출처 명시.
5. **미완의 닫기**: 단정 대신 독자에게 넘기는 질문 한 줄.
6. **자연스러운 CTA**: 글 주제에 맞는 1개만 (강의 문의 / IDEN 진단 / 책 발췌 / 뉴스레터). 광고 어조 금지.
7. **내부링크 2개**: 관련 lecture/book/iden 페이지 + 같은 시리즈 이전 글.

### 4.2 네이버 SEO 규칙
- 제목: 핵심키워드를 앞쪽 12자 이내 배치. 역할/감정어 결합("신임팀장이 가장 많이 후회하는 한 자리").
- 분량: 본문 1,200~1,800자(공백 제외) 권장. 이미지/도식 1개 이상(원본만, 스톡 금지).
- 태그: 기둥 대표 키워드 3 + 롱테일 2 (§ keywords.html 50개 풀에서).
- 가독성: 한 문단 3줄 이내, 모바일 기준.

### 4.3 AI검색(GEO) 규칙
- 글 상단/중단에 **"인용 가능한 단언문"** 1~2개를 독립 문장으로.
- 가능하면 정의형 문장("X란 …이다") 포함 → LLM 발췌 적합.
- 날짜·출처·저자 명시(llms.txt 가이드 준수): "2026-05 기준", 출처 URL.
- 고유 용어는 풀어쓰기 1회 병기(IDEN = 진로 좌표 진단) → AI가 개념-저자 연결.

## 5. 100점 품질 루브릭 (발행 게이트) ★핵심

> **설계 원칙**: "이상에 가까울수록 점수"가 아니라 **"필수 항목을 전부 충족하면 100점"인
> 체크리스트**. 따라서 100점은 도달 가능한 게이트다. 발행은 **6개 영역 100점(=모든 must 항목 충족)**일 때만.
> 미달 시 엔진은 **미달 항목만** 재작성 후 재채점(최대 5회). 5회 초과 시 사람에게 에스컬레이션.

| 영역 | 배점 | must 항목(모두 충족해야 만점) |
|---|---|---|
| 1. 검색·AI 노출 | 25 | 제목 앞 12자 내 핵심키워드(8) / 인용가능 단언문 1+ (7) / 정의형 문장 1+ (5) / 태그 5개·롱테일 2 (5) |
| 2. 깊이·독창성 | 25 | 고유 IP 1+ 구체 적용(10) / 실제 일화·사례 1+ (10) / 일반론 아닌 구체 디테일(5) |
| 3. 브랜드 보이스 | 15 | 1인칭 관찰자 톤(5) / 미완의 닫기(5) / 핵심좌표 연결(5) |

### 5.1 must-pass 방화벽(영역 점수와 무관하게 1개라도 위반 시 발행 차단)
- 지어낸 인물/통계/인용 → 즉시 0점·재작성.
- 핵심좌표("이타성")와 무관한 순수 정보 나열 → 차단.
- 광고성 과장 CTA(예: "지금 바로 신청하세요!!") → 차단.
- 타 저작물 무단 사용(특히 SBM은 저작권자 사전협의 영역) → 차단.

## 6. 운영 모델 (맥 엔진이 매일 실행)

- **스케줄**: launchd/heartbeat로 1일 1회 기동, 3편 생성까지 진행(이미 `task_schedule_launchd`는 green).
- **선택 로직**: 기둥 배분 잔여 + 시리즈 잔여를 고려해 다양성 유지(같은 기둥 연속 2편 초과 금지).

- **무중단 보장**: 재작성 5회 초과·연속 실패 시 그 글은 보류(skip)하고 다음 글로 진행 → 큐가 멈추지 않음.
- **상태 추적**: `agent/state/`에 진행 카운터(작성/발행/보류, 기둥별 잔여) 기록 권장.

## 8. 61~500편 생성 규칙 (엔진이 자동 확장)

## 10. 맥 엔진 연동 방법

이 문서는 이 레포(nedabahway-site)에 보관된다. 맥 에이전트가 소비하려면:

1. 이 브랜치를 맥에서 pull 한 뒤, 이 파일을 `~/Scripts/agent/blog_auto/` 가 읽는 위치로 복사하거나 심볼릭 링크.
2. `blog_auto` 엔진이 (a) 기둥/시리즈 잔여, (b) §4 템플릿, (c) §5 루브릭 JSON을 입력으로 받도록 연결.
3. 100점 통과분을 `blog_naver_publish` 액션으로 발행(이미 yellow=자동승인 처리됨).

> 정확한 배선(엔진이 읽는 입력 경로·함수)은 `agent/blog_auto/` 코드를 확인해야 1:1로 맞출 수 있다.
> 그 코드를 공유해주면 이 마스터플랜을 그대로 먹이는 어댑터까지 작성 가능.
