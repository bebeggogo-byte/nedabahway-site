> 작성: 2026-05-05 · 브랜치 `claude/save-conversations-feature-f2dJy`
> 상태: **사용자 승인 대기** — 승인 전 구현 금지
> 범위: 컨셉 설계 문서만 (구현·디자인은 별도 세션)

## 0. 본질 (한 줄)

> **Claude와의 대화는 "출처"가 아니라 "불꽃"이다. 불꽃에서 시작해 1차 자료에 닿은 결만 사이트에 남긴다.**

이 1줄이 모든 설계의 위에 있다. AI 대화 자체를 콘텐츠로 박제하지 않는다. AI 대화에서 발화된 *질문·각도·연결*을 단서로 삼아, 운영자(김창환)가 1차 자료를 다시 읽고 자기 결로 다시 짜는 작업이다.

학습페이지 전략 v1의 본질("30여 분야 섭렵")과 충돌하지 않는다. 오히려 보강한다 — 대화는 섭렵의 *경로*이고, 자료화된 노트는 섭렵의 *흔적*이다.

---

## 1. 문제 정의

### 1.1 현상

- Claude와의 대화 안에서 의미 있는 통찰·각도·연결이 자주 발생한다
- 그러나 대화창은 휘발성이다. 세션이 끝나면 흔적이 사라진다
- 캡처해도 *그 자체로는* 사이트의 톤·기준에 맞지 않는다 (학습노트는 1차 출처를 요구함)

### 1.2 풀어야 할 긴장

| 긴장 | A 쪽 | B 쪽 |
|---|---|---|
| 출처의 격 | 대화는 1차 자료가 아님 | 그러나 사고의 출발점이 됨 |
| 분량 | 대화 원문은 길고 산만함 | 통찰 자체는 한 두 문단임 |
| 공개 여부 | 사적 대화에 가까움 | 다른 이에게도 도움이 될 수 있음 |
| 톤 | AI가 생산한 문장은 평균적 | 사이트의 결은 매우 특정적임 |

이 긴장을 *층 분리*로 푼다. → §2

### 1.3 해결의 한 줄

**대화 원문은 사적으로 보관하고, 거기서 길어 올린 한 질문을 1차 자료로 다시 짠 결만 공개한다.**

## 2. 3-Layer 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1 — RAW (사적, 색인 안 됨)                            │
│   원본 대화 마크다운. 운영자만 봄.                          │
│   목적: 기억의 백업, 재참조, 후속 발굴                      │
│   위치: vault/dialogues/raw/  (noindex, .htaccess 또는 SW) │
├─────────────────────────────────────────────────────────────┤
│ Layer 2 — SPARK (사적·반공개, 운영자 작업장)                │
│   원본에서 추출한 한 질문/한 각도/한 연결.                  │
│   목적: 학습노트로 익히기 전 단계 메모.                     │
│   위치: vault/dialogues/sparks/                             │
├─────────────────────────────────────────────────────────────┤
│ Layer 3 — PUBLISHED (공개)                                  │
│   1차 자료로 다시 짠 결. 학습노트 또는 매거진 형식.         │
│   목적: 사이트 독자에게 전달.                                │
│   위치: learning/notes/ (기존) 또는 learning/dialogues/(신설)│
└─────────────────────────────────────────────────────────────┘
```

### 2.1 층 간 흐름

```
Claude 대화 발생
   ↓ (수동 복붙)
RAW 저장 — vault/dialogues/raw/raw-2026-05-05-{slug}.md
   ↓ (운영자가 한 질문/각도 추출)
SPARK 메모 — vault/dialogues/sparks/spk-2026-05-05-{slug}.md
   ↓ (1차 자료 1~3개 추가 + 운영자 결로 다시 씀)
PUBLISHED — learning/notes/lrn-... 또는 learning/dialogues/dlg-...
```

### 2.2 각 층의 자율성

- RAW는 *완성도 0*이어도 된다. 그저 보관일 뿐
- SPARK는 *완성도 30*이어도 된다. 운영자 메모일 뿐
- PUBLISHED는 *완성도 90 이상*. 사이트 톤·인용·검증 다 통과

## 3. 분류 체계 — 어떤 대화가 자료화 대상인가

### 3.1 자료화 가치 4축

대화 마치고 *마크하기 전에* 운영자가 1축 이상에 해당하는지 확인:

| 축 | 질문 | 예시 |
|---|---|---|
| Q. 새 질문 | 이전에 못 묻던 질문이 떠올랐는가 | "정약용 유배기와 아인슈타인 1905의 공통 구조는?" |
| A. 새 각도 | 같은 주제를 다른 방향에서 보게 됐는가 | "코칭을 '질문'이 아니라 '거울'로 보면" |
| C. 새 연결 | 분리되어 있던 두 영역이 이어졌는가 | "퍼실리테이션과 신학의 회중 개념" |
| F. 약점 노출 | 내 사고의 빈 곳이 드러났는가 | "리더십을 가르치면서 정작 위임을 못 함" |

4축 모두 미해당이면 RAW만 저장하고 SPARK·PUBLISHED로 올리지 않는다.

### 3.2 학습페이지 6영역과의 연결

기존 6영역(고전·인문·과학·실무·자기이해·예술자연) 분류를 그대로 사용한다. 신규 분류 만들지 않는다.

대화에서 발생한 통찰은 반드시 6영역 중 1~2개에 매핑되어야 한다. 매핑되지 않으면 자료화 대상 아님.

## 4. 메타데이터 스키마

### 4.1 RAW 파일 frontmatter

```yaml
---
type: raw
date: 2026-05-05
slug: brief-descriptor
session_origin: claude.ai | claude-code | api
duration_estimate: 30min
state: captured | extracted | exhausted
---
```

`state` 흐름: captured(저장만) → extracted(spark 1개 이상 추출됨) → exhausted(더 길어 올릴 게 없음)

### 4.2 SPARK 파일 frontmatter

```yaml
---
type: spark
date: 2026-05-05
slug: einstein-1905-jeju-parallel
parent_raw: raw-2026-05-05-einstein-1905-jeju-parallel.md
axis: Q | A | C | F          # §3.1
domain: [고전, 과학]         # §3.2 6영역
one_question: "정약용 유배기와 아인슈타인 1905의 공통 구조는 무엇인가?"
candidate_sources:
  - "Einstein, Annalen 17 (1905)"
  - "정약용, 흠흠신서 (1822)"
state: drafting | published | abandoned
target_format: learning-note | magazine-essay | dialogue-note
---
```

### 4.3 PUBLISHED — 기존 학습노트 스키마 그대로

기존 `lrn-YYYY-MM-DD-{slug}-N.html` 패턴을 그대로 사용. 추가 필드 1개만:

```yaml
spark_origin: spk-2026-05-05-einstein-1905-jeju-parallel.md   # 선택, 추적용
```

이 필드는 HTML 출력에는 안 나타난다. 빌드 메타에만 보관.

### 4.4 인용 표기 — 핵심 규칙

학습노트의 인용은 1차/표준 자료만 허용된다. 다음 표기는 **금지**:

- `[CLAUDE 대화]`
- `[AI 생성]`
- `[Anthropic Claude, 2026]`

대화는 출처가 아니다. 출처는 운영자가 따로 1차 자료에서 가져와야 한다.

대신 SPARK 단계에서만 다음을 허용:

```
출발점: claude 대화 2026-05-05 (vault/dialogues/raw/...)
```

이는 SPARK 파일 안에서만 쓰이고 PUBLISHED HTML에는 노출되지 않는다.

## 5. 파일·디렉토리 구조

```
nedabahway-site/
├── vault/
│   ├── dialogues/                    # 신설
│   │   ├── raw/
│   │   │   ├── raw-2026-05-05-{slug}.md
│   │   │   └── ...
│   │   ├── sparks/
│   │   │   ├── spk-2026-05-05-{slug}.md
│   │   │   └── ...
│   │   └── INDEX.md                  # 운영자용 색인 (사적)
│   └── (기존 vault 자산)
├── learning/
│   ├── notes/                        # 기존 — 기본 발행처
│   │   └── lrn-YYYY-MM-DD-{slug}-N.html
│   ├── dialogues/                    # 신설 (선택)
│   │   └── dlg-YYYY-MM-DD-{slug}.html
│   └── DIALOGUE_NOTES_v1.md          # 본 문서
└── scripts/
    └── (선택) dialogue-build.mjs     # 마크다운→HTML 빌더, MVP에선 없어도 됨
```

### 5.1 `learning/dialogues/` 신설 vs `learning/notes/` 흡수

두 옵션:

**옵션 A — 흡수**: 모든 PUBLISHED는 기존 `learning/notes/`에 들어간다. 대화 출처를 굳이 분리하지 않는다.
- 장점: 독자 입장에서 통일됨, 빌드 단순
- 단점: 대화 시리즈로 묶어 보여주기 어려움

**옵션 B — 분리**: 대화에서 출발한 노트는 `learning/dialogues/dlg-...`로 별도 발행.
- 장점: "AI와의 대화에서 출발해 1차 자료에 닿은 결"이라는 메타 시리즈가 가능
- 단점: 분류가 늘어남, 독자에게 "왜 분리됐는가" 설명 필요

**권장 (사용자 결정 사항 ②)**: 옵션 A로 시작. 12편 이상 누적되면 옵션 B로 분리 가능. 시리즈 정체성보다 결의 일관성이 먼저.

## 6. 워크플로우 — 수동 복붙 흐름

### 6.1 1단계 — 캡처 (대화 직후, 5분)

1. Claude 대화창에서 인상적인 부분을 통째로 복사
2. `vault/dialogues/raw/raw-YYYY-MM-DD-{slug}.md` 파일 생성
3. frontmatter 채우고 대화 원문 붙여넣기
4. 끝. 더 손 안 댐.

### 6.2 2단계 — SPARK 추출 (대화 후 24시간 이내, 15분)

1. RAW 파일 다시 읽음
2. §3.1 4축 중 어디에 해당하는지 판단
3. `vault/dialogues/sparks/spk-...` 파일 생성
4. `one_question` 필드에 한 질문으로 압축
5. `candidate_sources` 후보 1차 자료 1~3개 메모
6. `state: drafting`으로 둠

### 6.3 3단계 — PUBLISHED 작성 (며칠 내, 60~120분)

1. `candidate_sources` 1차 자료를 실제로 읽음 (대화는 더 이상 보지 않음)
2. 운영자 결로 다시 씀 — 학습노트 톤 (§7)
3. `learning/notes/lrn-YYYY-MM-DD-{slug}-N.html` 생성
4. SPARK 파일 `state: published`로 변경, `spark_origin` 추적 메타 보존
5. 사이트 빌드·배포 기존 절차 그대로

### 6.4 사라지는 경로

- RAW만 있고 SPARK 안 만들어진 채 30일 경과 → `state: exhausted` 표시
- SPARK가 `drafting` 상태로 60일 경과 → `state: abandoned` 표시 또는 다른 SPARK와 병합
- 매월 1회 운영자가 vault/dialogues/INDEX.md 갱신

## 7. 톤·문체 가이드 — 기존 결 유지

기존 학습노트(예: `lrn-2026-04-30-einstein-1905-1.html`)의 결을 그대로 따른다. 새 결을 발명하지 않는다.

### 7.1 유지해야 할 결

- 짧은 문장, 한국어 중심
- "한 사람", "한 해", "한 줄" 같은 추상명사 + "한"의 패턴
- "장소" 대신 "곳" 사용
- 영문 인명·서명은 원어 그대로
- em-dash(—)로 호흡 끊기
- "그러나 반대 의견도 있다", "표면 아래를 들여다보면" 같은 검증 마커
- "다음 단계는 ...로 이어진다"로 마무리

### 7.2 대화 출처 글에서 특히 조심할 것

- AI 문체 잔여물 제거: "다양한", "효율적인", "최적화", 불릿 폭발, "여러분"
- "Claude가 말하길..." 같은 메타 진술 금지 — 1차 자료 인용으로만 발언
- 운영자 1인칭 시점 유지

### 7.3 검증 체크리스트 (발행 직전)

- [ ] 1차 자료 1개 이상 직접 인용했는가
- [ ] AI를 출처로 표기하지 않았는가
- [ ] 한 사람·한 해·한 줄 결을 유지했는가
- [ ] em-dash·곳·결의 어휘가 살아있는가
- [ ] 마지막 문단에 "다음 단계는..."이 있는가
- [ ] 6영역 중 어디에 속하는지 명확한가

## 8. 인용 윤리 — 한 절로 정리

이 사이트의 약속은 "1차 자료에 닿는 것"이다. AI 대화를 출처로 인용하는 순간 그 약속이 깨진다.

따라서 다음을 원칙으로 못 박는다:

- **AI 대화는 *발견의 도구*이지 *출처*가 아니다**
- AI가 인용한 자료는 운영자가 직접 확인한 후에만 신뢰한다 (할루시네이션 가능성)
- 발행물에 AI 기여를 표기하고 싶다면, `learning/notes/`가 아니라 별도 메타 페이지(예: `/about/method.html`)에 한 번 명시한다
- 개별 노트마다 "이 글의 출발점은 AI 대화였다"고 표기하지 않는다 — 모든 글은 결국 운영자의 결이기 때문

## 9. 사이트 통합 지점 — 최소 변경

이 컨셉이 채택되면 사이트에서 바뀌는 것은 *작다*. 기존 `learning.html` 인덱스에 새 글이 추가되는 것 외에 표면적 변화 없음.

### 9.1 변경 없음

- learning.html — 기존 매트릭스에 새 lrn-... 파일이 자동 노출
- 기존 학습노트들 — 손 안 댐
- 사이트 메뉴·네비게이션 — 변경 없음

### 9.2 변경 있음 (선택, 옵션 B 채택 시)

- learning.html에 "대화에서 출발한 결" 필터/태그 추가
- learning/dialogues/index.html 1페이지 신설
- 메뉴에 노출 여부는 12편 누적 시점에 재결정

### 9.3 vault 영역

- vault/dialogues/는 **반드시 noindex**
- robots.txt에 추가
- vault/sw.js (Service Worker)에서 캐시 제외 또는 사적 인증 게이트

## 10. MVP 정의 — 최소 출발선

이번 작업의 다음 세션에서 만들 것 (구현 단계, 별도 세션):

### 10.1 MVP 포함

1. `vault/dialogues/raw/` 디렉토리 생성 + .gitignore 또는 noindex 보장
2. `vault/dialogues/sparks/` 디렉토리 생성
3. `vault/dialogues/INDEX.md` 운영자용 색인 시드 1개
4. RAW 마크다운 템플릿 1개 (`vault/dialogues/_templates/raw.md`)
5. SPARK 마크다운 템플릿 1개 (`vault/dialogues/_templates/spark.md`)
6. 첫 RAW → SPARK → PUBLISHED 1회 사이클 시범 (1편)

### 10.2 MVP 비포함 (나중)

- 자동 빌드 스크립트 (마크다운→HTML 변환)
- vault 인증 게이트
- 대화에서 출발한 노트 전용 필터
- learning/dialogues/ 분리 (옵션 B)
- 통계·분석 (RAW/SPARK/PUBLISHED 전환율 등)

## 11. 사용자 결정 사항

본 문서의 승인 전에 운영자가 답해야 할 질문 5개:

1. **결정 ① — vault 보호 수준**: vault/dialogues/는 (a) git에서 빠짐 (b) git에 들어가되 noindex (c) 별도 사설 저장소
2. **결정 ② — 발행 분기 정책**: 옵션 A(흡수) vs 옵션 B(분리, learning/dialogues/) 중 시작점
3. **결정 ③ — RAW 보존 기한**: 무기한 vs N일 후 자동 archive vs 운영자 수동 정리
4. **결정 ④ — Slug 명명 규칙**: 한국어 음차 vs 영문 키워드 (기존 lrn-은 영문 사용 중)
5. **결정 ⑤ — 첫 시범 1편 주제**: MVP 사이클을 돌릴 *현재 진행 중인 대화* 1건이 이미 있는가, 새로 시작할 것인가
